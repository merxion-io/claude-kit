# Kind of work → model and effort: the measurement of 2026-10-28

For people. Agents read only the decision: `skills/orchestration/references/routing.md`.

The table comes from measuring transcripts (`tools/task-kinds.py`), not from the orchestrator's memory. The choice:
mechanics on a decided contract → sonnet; judgment, money, schema, concurrency, new work without a pattern → opus; doubt → opus.
The ceiling is the role's `maxTurns` (builder 100, code-reviewer 100, scout 40, verifier 40); "budget" is the median/p90 of turns.
Effort is almost never set explicitly in runs (of 1220 — in ~15 %), so the column is a recommendation, not a measurement:
roles by default (scout low, builder medium, review high); high for a builder — only with an explicit reason in the plan.

Why so:
- Sonnet gave not a single handoff on mechanical kinds; no kind crossed the threshold ">30 % — opus", so switching to
  opus by this rule is not needed. Caveat: sonnet took simpler pieces, 0 % is not a guarantee.
- Candidates for sonnet, to verify: delta merge, tests by contract, cleanup, cabinet/UI. Opus does them more expensively
  and with handoff 13–23 % against 0 % for sonnet. Switch after 2 weeks of measurement on a sample of equal complexity.
- Engine logic, proposal, measurement stay opus: expensive and 24–27 % handoff — cut subtasks smaller (p90 is above the ceiling).

Recomputation:
- `python3 ~/.claude/tools/task-kinds.py --since <date>` prints the table (kind names as in the rows above); `--json` — for comparison with the previous one.
- Review once a week and when a kind gets more expensive ($/each grows 30 % from the row above) or handoff > 30 %.
- The "other" row must be ≤ 15 % of runs; otherwise extend the `KINDS` word table at the top of the script.
- A new measurement goes to a new file here (`routing-<date>.md`), the decision table in the skill is updated by it; put date and N; N < 10 — mark "little data" and do not change the model by it.
