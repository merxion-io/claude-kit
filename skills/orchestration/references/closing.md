# A milestone closes only when it is done

Plan = list of items (`tasks.md`, checklist, issue); closing = all marked done.

- An open item is a prohibition: close (archive, Review, "done" to the owner) only when ALL are closed; a reason beside an item does not legitimize it.
- Close a fallen agent's work in ITS item. "Done but not marked" does not exist: reconcile by meaning, not name.
- An open item is yours; "don't know" and "report and leave" are not outcomes. First, aloud: why it happened (usually an architectural error of a
  neighbouring decision) — name it; another mechanism; a workaround (smaller piece, another seam, move the decision, drop an extra
  requirement); what is right architecturally (no second home, judge or source of truth).
- No third state. Keep asking about open items during the milestone: found mid-way — solve architecturally; on delivery day — only formalised.

## An item moves in only two ways
1. A measurement showed it is not needed or harmful → delete it with the measurement.
2. It is a different subject → separate task; the reason names the BOUNDARY ("this is about X, the milestone about Y"),
   not difficulty. "Hard", "risky", "no data", "needs refactoring" are not moves.

## A reason for refusal
"Impossible, because X" — show X by a command first.

## Traces
- Task folder: report, replay script, minimal inputs; raw responses, page copies, caches, attempts, dumps → temp dir, deleted after.
- Status = one short file, readable phrases, no glued cipher.
- Candidate in a separate copy: from current `HEAD`, deleted after the commit.
